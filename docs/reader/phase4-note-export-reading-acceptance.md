# 第四阶段：私人笔记导出与继续阅读验收

2026-10-29（Asia/Shanghai）。基线 `9bf668e`，在 Linux 本机 `codex/article-reader` 工作树完成实现、独立审查及本机更新，未推送或公开上线。

## 使用

登录后，在单篇文章“私人阅读”区点击“导出笔记 Markdown”。普通文章页的私人工具、私人当前正文及历史正文页均有入口。文件包含当前文章的标题、作者、来源、原文链接、发布时间与收录时间、分类与主题名称、收藏和阅读状态、已保存笔记及其版本与时间；YAML frontmatter 可用于 Obsidian，笔记保留原有 Markdown 文本。没有发布时间时为null，不冒充收录时间；空笔记有明确提示。

导出只读取服务端已保存内容，不隐式保存草稿，不修改文章、笔记、收藏、状态、分类主题、归档或审计。其他窗口已保存的新笔记会进入文件；当前页面草稿保留。下载失败留在原页，会话失效使在途下载失效。历史正文页导出的仍是文章当前信息与已保存笔记，文件不包含历史正文或图片；原有指定版本 ZIP 继续用于正文和资源，并不加入私人笔记。

私人当前正文和历史正文支持章节目录、当前章节提示、手机折叠目录及“继续阅读”。重新打开后由读者点击恢复，不在载入或程序恢复时覆盖旧位置。目录定位遵循减少动态效果设置，可通过键盘操作。手机目录当前标题单行截断，展开后显示完整目录；提示区域预留高度，避免收起继续阅读提示时移动正文。

阅读操作后合并保存位置；隐藏或离开页面时尽力发送最后一笔。收藏及待读/在读/已读仍手动设置，不因滚动自动变化。保存冲突或失败会停止自动保存，可“载入阅读位置”核对后继续。最后一段进度不能保证在断电或断网时提交成功。位置按章节及章节内比例恢复，窗口宽度变化后不承诺精确到同一个字；图片或正文布局高度变化时保持恢复定位，直到读者开始操作。

## 数据与权限

GET `/api/admin/reader/articles/:id/note.md` 由统一管理员会话保护并返回 `no-store`，使用只读一致性事务读取元数据和笔记。未公开、下架或没有正文的文章仍可导出。元数据按 JSON 字符串编码到 YAML，正文标题转义，下载文件名使用稳定文章ID；私人资料不进入公开文章响应或原有正文ZIP。

迁移 `0103_reader_positions.sql` 仅创建独立表 `reader_positions`，无回填、旧资料改写、新依赖或环境变量。GET/PUT `/api/admin/reader/snapshots/:snapshotId/position` 均须登录，写入另须CSRF。位置有独立版本并按CAS保存，冲突不取新版本重放旧位置；自动位置不写高频审计，也不改变笔记或私人状态版本。记录随完整数据库dump保存，不存入浏览器持久存储。

位置身份由文章ID、原始快照正文HTML、格式与定位规则版本确定。不能只用bodyRevision：既有归档允许同一修订有不同HTML。标题、作者、来源名变化且正文相同时可继续使用原位置；正文改变则独立保存，并提供之前阅读版本的入口。目录身份从不可变正文生成，图片pending/failed/ready不改变允许保存的章节；响应生成的锚点不改快照原文或ZIP。
