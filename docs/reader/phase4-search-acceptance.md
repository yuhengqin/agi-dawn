# 第四阶段：私人书库关键词搜索验收

日期：2026-10-28。基线57250d9，继续在 `codex/article-reader` Linux隔离工作副本实现并更新本机服务，未推送或公开上线。本批仅增加已确认的私人关键词搜索，不包含批量编辑、主题管理器或自动分类。

## 使用与范围

[私人书库](http://localhost:3000/admin/reader)增加“关键词”输入，可搜索显示标题、摘要、当前已保存正文和已保存私人笔记，并与来源、类别、主题、收藏、阅读状态取交集。结果标明命中字段及最多160个Unicode字符的纯文本上下文；正文与笔记全文不随书库列表返回。

最多输入200字符、6个词，大小写不敏感，空格及既有中英文相邻边界分词；每个词均需在四种字段之一命中，允许跨字段。`%`、`_`、反斜杠按普通字符匹配。空白表示不搜索；按Enter或点击“筛选”提交。刷新、返回和翻页保留条件，改词后重筛回到第一页，“清除筛选”同时清除关键词。

正文只使用与当前文章的正文版本和完整表示哈希精确匹配的已保存快照；不使用可能陈旧的 `body_text`，也不以某个历史快照兜底。正文图片仍在保存中或存在明确partial时，已保存的当前正文仍可检索；没有当前快照时标题、摘要和笔记仍可查。未保存笔记草稿和历史正文版本不参与搜索。人工清空摘要后不回退原摘要。

私人历史继续包含下架文章、停用来源与未发布材料，缺省状态仍是未收藏/待读。所有搜索数据只从管理员API返回，保持 `no-store` 和失效卸载；不写公开搜索索引，不改变公开全文权限，不调用模型或抓取服务。关键词随GET条件保留在本机浏览器地址历史；API访问日志去除query string，未添加私人内容日志。

## 发现并处理的问题

初版复用的通用去标签函数把每个标签当作空格，导致 `Open<strong>AI</strong>` 和高亮代码 `foo<span>.</span>bar` 无法按阅读时的连续文字检索。现有测试中补充失败复现，再改为保留内联文字、只在块元素及换行处分隔的DOM文字提取，断词、块边界、哈希失配等断言通过，并重跑完整后端检查。

真实集合验收脚本也曾把不同段落的“10”和“0%”直接拼成“100%”，产生错误预期；检查最小HTML节点确认是验证脚本漏加块边界，修正预期提取后43组查询全部通过，没有修改业务逻辑去迎合该错误预期。

日志、只读数据摘要、性能记录与截图保存在本机忽略目录 `.data/private-search/`。更新与旧分页链接处理见[部署说明](../deploy.md#更新与回退)。
