# 第四阶段：网页主题管理验收

验收记录日期：2026-10-29（Asia/Shanghai）。实施始于2026-10-28，基线 `4f08522`，继续使用 Linux 本机 `codex/article-reader` 工作树，未推送或公开上线。

## 使用

[主题管理](http://localhost:3000/admin/reader/topics)已加入后台“私人阅读”导航。列表展示主题名称、说明和关联篇数，点击篇数可进入对应私人书库；书库及单篇主题表单也有管理入口。

新增填写名称和说明；展开“编辑主题”可改名、编辑说明。名称去首尾空白后1–60字符，唯一且不能换行；说明1–2000字符，可分段。保存中禁用该表单，失败保留输入。冲突后可显式“载入已保存版本”再调整，不清除其他表单草稿。保存成功后的目录刷新若失败，保留当前列表和其他未保存输入，可“重试刷新主题列表”，不会重复保存；会话过期卸载私人控件并转登录。

改名只改变显示信息，不改变原链接和已有文章归属。新增和修改后，各入口下一次读取即使用最新目录；已打开的其他页面可刷新获取，无需重启API。新增不会自动给文章分配主题，可用既有单篇勾选或批量整理完成。

## 数据与读取

新增 `0101_article_topics.sql`，单条DDL仅创建 `article_topics`。初始14项由显式 `scripts/seed-topics.ts` 导入；新安装的 `scripts/seed.ts` 也调用同一初始化。原slug、名称、说明、匹配标签及顺序逐项保留。重复初始化不覆盖管理员编辑，即使旧名称已被另一个新主题使用，也保持两者身份独立。

运行时主题项统一从数据库读取，替换原进程内数组和同步查找，不增加目录缓存、轮询或文章关系回填。文件保留为初始模板及分组配置；网页新增技术主题，不修改分组。名称、说明更新与审计在同一事务内提交，版本冲突与重名拒绝。slug和匹配标签不能通过管理API修改；新主题使用独立内部标记，普通文章标签不展示该标记。

管理篇数与私人书库主题筛选使用相同的发布投影标签，包含已下架及暂停来源的历史；普通主题统计和发现入口继续使用公开可见性规则。公开详情、主题页、搜索建议和分享图，以及私人筛选、主题勾选、批量整理，都读取同一目录。私人笔记、收藏、状态和快照仍受管理员保护。
