# 第四阶段整体验收与新版备份恢复演练

2026-10-29（Asia/Shanghai），基线 `b92e904`，在 Linux 本机 `codex/article-reader` 工作树完成。本轮补强恢复回归测试及验收记录，未修改产品功能、数据库迁移、依赖或环境配置，未推送或公开上线。

## 演练方式

采用两次恢复：

1. 暂停已核实归属的当前worker与备份/观察timer，API和web保持原实例运行。记录当前书库业务表、图片及既有备份文件的摘要。
2. 将需备份资源复制到本次0700目录，以当前reader_dev生成新的本地完整配套备份。备份输出也在本次目录，避免触发原 `.data/backups` 的三组轮转删除；既有 `backup.last` 运维记录随正常备份更新。
3. 创建独立准备库及资源目录并恢复。核对业务表摘要与原库一致，校验ready资源。只在准备库通过现有接口建立专用非空私人资料，保留原有文章、分类、主题、快照及资源。
4. 记录私人资料原文、版本、时间、视图条件及正文位置身份，生成新版配套备份，再恢复到第二个新建空库及空目录。
5. 启动前核对完整业务摘要及资源；使用独立凭据和随机本机端口启动恢复API/web，检查恢复后功能。隔离环境无worker，采集、模型、通知与IndexNow均关闭，不继承真实外部集成配置。
6. 关闭所有隔离进程，比较原书库、原图片及原备份文件，恢复当前worker和timer，核对active及原站smoke后才写完成标记。

最终恢复库的验收资料来自准备库的备份，没有在最终库重新创建笔记、状态、视图或阅读位置。浏览器只打开已有记录、搜索、点击继续阅读和导出，不提交私人修改。

## 功能验证结果

- 恢复API返回笔记、收藏状态、两个视图及位置的完整原值；所有业务表在浏览器验收后仍与备份前相同。
- 笔记关键词搜索与原五条件、笔记有无及排序交集正确；已保存正文可搜索；打开已恢复视图查询当前结果。
- 私人图片HTTP响应逐个核对大小和SHA256，网页图片实际加载；章节目录、当前章节及已有位置的“继续阅读”在两种浏览器三种宽度均正常。
- 单篇笔记Markdown与备份前文件逐字一致；批量ZIP每个条目与单篇一致，三篇选择包含无笔记文件。浏览器完成12次实际下载，未保存草稿没有进入文件，草稿保留。
- 指定版本正文ZIP的文件集合、正文、Markdown、图片与metadata均与备份前一致，清单逐文件核对大小及SHA256，正文ZIP不含私人笔记。
- 解包后的article.html在Chromium和WebKit打开，本地图片全部完成加载，HTTP/HTTPS请求数为0。Chromium额外启用离线模拟；Linux WebKit的离线模拟连最小file页面也报内部错误，故WebKit使用阻断全部HTTP/HTTPS请求的方法验证独立离线文件，不将该驱动限制归为文章或恢复故障。
- 匿名私人请求401；恢复后的已登录会话仍须CSRF，缺少令牌的笔记、状态和批量导出请求均403。公开响应不含验收笔记，会话退出后私人内容清除。
- 对最终恢复目录内的一个图片文件故意写入损坏内容，校验明确拒绝；用该文件原恢复字节修复后再次全量校验通过。原图片目录未参与损坏测试。

Chromium/WebKit各1440、390、320px，共6组；无横向溢出、脚本错误、外网请求或意外私人写请求。已检查WebKit320px继续阅读和Chromium离线页面截图。
