# 私人笔记导出与继续阅读

用户已授权本机 Linux 实现：先单篇私人笔记 Markdown 导出，再目录导航与跨次继续阅读；不公开上线。

## 导出

登录后在私人阅读工具中下载 Markdown。文件包含文章标题、作者、来源、原文链接、发布时间（缺失时明确为空）、收录时间、分类名称、主题名称、收藏与阅读状态，以及服务端已保存笔记及其版本、保存时间。文件使用 YAML frontmatter（值按 JSON 字符串安全编码）与可读 Markdown 正文。私人笔记按已保存文本保留，空笔记明确显示；不夹带全文或资源。

GET `/api/admin/reader/articles/:id/note.md` 经统一管理员会话检查、no-store；在只读一致性事务中读取，未公开、下架或无正文的文章仍可导出。导出不保存草稿、不修改文章、笔记、状态、归档和审计。界面通过鉴权 fetch 下载，错误留在当前页，草稿不受影响；会话失效沿用清除私人资料的规则。

## 阅读体验

私人当前正文与历史正文均有章节目录，显示当前章节，手机可展开目录；复用现有正文渲染与滚动辅助函数。正文标题生成确定的章节锚点，原始归档和 ZIP 保持原样。

阅读位置在服务端独立保存，不共用收藏/阅读状态的版本。新增 `0103_reader_positions.sql` 单条 CREATE TABLE，主键 `(article_id, body_hash)`；`body_hash` 为原始不可变快照的 formatVersion、正文 HTML 与定位规则版本的 SHA256，资源就绪状态和标题/作者/来源等元数据不参与。不能只按 bodyRevision 匹配：既有快照测试证明同修订也会出现不同 HTML。记录最近保存所在 snapshotId，保留其他正文的独立位置，不自动套用。

GET/PUT `/api/admin/reader/snapshots/:snapshotId/position`，读返回当前正文位置和最近其他正文位置；写为 `{expectedVersion,anchor:null|sec-N,offset:0..1,progress:0..1}`。服务端验证锚点属于该快照，INSERT/UPDATE CAS，409不取新版本重放。进度不写审计（自动高频私人位置），不改其他业务表。未保存返回null，不创建行。

重新打开后提供“继续阅读”，由读者选择恢复；普通访问、路由历史滚动或程序恢复不把原位置覆盖成页首。显式目录操作或滚动意图后才启用保存，合并并串行写入；离页或隐藏时尽力发送最后一个位置（带会话CSRF的keepalive请求），网络/冲突停止自动保存并提供载入记录再继续的入口。记录章节及章节内相对位置，适应视窗变化；图片迟加载时，恢复定位保持稳定直到读者开始操作。会话失效接入后台边界卸载，不覆盖其他窗口的新位置，不改笔记、分类主题、收藏或阅读状态。不向浏览器持久存储写阅读数据。

## 验收

后端鉴权、CSRF、Markdown 元数据边界、只导出已保存笔记与只读性；进度跨访问/版本/并发与独立性。浏览器实际下载、草稿保留、错误与会话失效、目录/当前章节、手机导航、继续阅读与图片变化。完整 typecheck、后端测试、web 构建和 web 测试，再备份、仅本机更新、真实下载与多视口验收；记录业务数据不变的证据。
