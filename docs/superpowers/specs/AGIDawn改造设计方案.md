# 基于 AGIDawn 的 LLM 与 Agent 文章阅读站改造设计

状态：设计已确认，用户已于2026-10-27授权在本机 Linux 实现与验证。

本方案针对 `D:/AgentPro/AGIDawn` 的 `main` 分支、提交 `aa8e5b1`。建议以它建立独立项目，复用采集、正文处理、阅读界面和管理认证，改成以原始文章为中心的公开阅读站。实施时使用隔离工作副本和全新数据库，保留原项目及已有数据。

## 1 已确认的需求

| 已确认事项 | 第一版应有的行为 |
| --- | --- |
| 公开给所有人使用 | 访客无需注册或登录即可浏览和阅读全文 |
| 集中追踪关注的网站 | 接入选定来源后，定时收集更新，新文章自动出现 |
| 在站内阅读 | 展示原始正文，保留作者、来源、时间和原文链接 |
| 管理员可以移除 | 从公开网站下架文章，同一篇文章再次采集或处理时不自动恢复 |
| 组织文章 | 按来源、主题、时间浏览和搜索，支持查找旧文章 |
| 个人积累只服务站主 | 收藏、阅读状态和简单读后感仅供管理员本人使用 |
| 保存并反复阅读 | 保留文章内容，支持将正文与图片导出到本地 |

用户已选择统一的网站，并已确认本文关于独立项目、数据保存、原文优先、发布异常处理及功能分期的设计。原规划轮次仅拆分计划；后续指令已授权在本机 Linux 开始开发。

成功的日常使用场景：你每晚打开这一个网站就能检查新文章、完成阅读和收藏；将网址分享给其他人，对方无需账号即可阅读。重要文章能够按主题重新找到，保存的文章不因原站图片失效而立即失去阅读价值。

## 2 路线选择与第一版边界

| 路线 | 收益 | 代价 | 结论 |
| --- | --- | --- | --- |
| 基于 AGIDawn 独立改造 | 复用已经衔接的采集、存储、去重、阅读、管理能力 | 必须调整发布规则，并清理不再使用的热点业务 | 推荐 |
| 抽取采集器或阅读组件，另建系统 | 新系统可以完全按阅读站组织 | 需要重新连接任务、存储、权限、下架、导出等能力 | 暂不采用 |
| 现有阅读工具加独立公开网站 | 可利用现成的个人阅读功能 | 需要额外处理文章、分类、删除和笔记的同步 | 不符合已选择的统一操作方式 |

第一版完整交付包括公开阅读、自动收录、管理员维护、来源与时间筛选、私人收藏与读后感、含图片的离线保存。下文的第一个实施阶段只是可验收的中间成果，不代表全部需求已经完成。

第一版不提供普通读者账号、公共评论、社区投稿、个性化推荐、自动周报或热点排名；不把 Obsidian 作为运行依赖。自动摘要、翻译和 AI 分类不进入首版关键流程，未来需要时再增加。首版保留原文语言，不强制改写标题或翻译正文。

暂不提供全站历史爬取、付费内容获取、视频音频离线下载、原网页脚本和互动组件的复制，也不提供从正在运营的 AGIDawn 数据库直接升级的迁移承诺。

## 3 产品使用方式

公开部分包含最新文章、来源目录、主题浏览、搜索和文章阅读。默认按文章时间倒序展示；有可信原文发布日期时使用该日期，否则明确显示收录时间。原文发布时间、首次收录时间、内容更新时间分别保存，后续处理和重新抓取不把旧文章顶成新文章。

来源、内容类型和主题分开管理。来源对应具体作者、机构或博客栏目；主题允许一文多标签。第一版可继承来源默认标签，由管理员修正单篇文章。具体分类词表留在 `industry/` 配置中，不在共享逻辑写死；技术实践、经验总结、观点讨论等仅作为初始候选，最终词表待确认。

文章页以正文阅读为主，展示原始标题、作者、原文日期或收录日期、来源与原文链接。缺失作者或日期时如实留空或使用明确标签，不由模型补造。保留目录、图片查看、代码复制等现有阅读能力。只有管理员看到自己的收藏、阅读状态和读后感入口；这些数据通过独立的受保护接口获取。

阅读状态先采用“待读、阅读中、已读”。打开文章可以进入阅读中，只有显式标记才算已读；收藏独立于阅读状态。第一版不要求精确恢复滚动位置。读后感是一段可编辑文本，保存时间可见，无需高亮批注、双向链接或评论楼层。

## 4 自动收录与发布

正常流程为：

```text
启用的来源
  → 定时读取更新
  → 识别文章身份、去重、记录原始元数据
  → 创建或更新公开文章条目
  → 异步提取并校验正文
  → 更新站内全文与保存的版本
```

新文章出现不需要管理员逐篇审核，也不需要模型评分通过。采集、正文提取和公开展示分别记录结果：已经发现文章不等于已经取得可靠正文。

| 情况 | 公开表现 | 后台处理 |
| --- | --- | --- |
| 允许站内全文，正文提取成功 | 在站内显示正文与原文链接 | 记录内容版本与资源保存状态 |
| 允许全文，但提取未完成或失败 | 条目仍出现，显示“全文暂未就绪”及原文入口；可用来源摘要正常展示 | 使用有界重试，管理员可查看原因及重新处理 |
| 来源只允许链接或摘要展示 | 显示已允许的元数据、摘要和原文入口 | 来源状态清楚标记，不能算作全文接入完成 |
| 正文被识别为不完整 | 明确提示内容不完整，保留原文入口 | 记录缺失问题，进入修复列表，不宣称完整归档 |
| 暂无可信发布时间 | 显示收录时间，并支持后续补齐原文日期 | 不虚构发布日期，不因缺日期永久阻止收录 |
| 管理员下架 | 从公开列表、搜索、详情和公开资源访问中移除 | 保留内部文章身份与人工决定 |

“正文提取成功”表示结构检查通过，不是对语义完整性的自动保证。重点来源仍需用真实文章人工对照原文，尤其是代码、表格、公式和图表。

首次接入默认沿用可配置的有限历史导入：最多 30 篇、近 12 个月，按原文时间归档；具体来源可调整。首次导入记录与后续增量边界分开，避免每轮重扫整个历史库。旧文章的保存和查找不设置“只能访问最新 2,000 条”的产品上限，分页与日期筛选必须能到达全部已公开记录。

停用来源只停止后续采集，已收录文章保留原公开状态；如需移除其历史文章，必须使用明确的下架操作。管理员下架以现有人工覆盖记录为准，后续采集、正文修订和异步任务都不得自动撤销。第一版保证同一规范化文章身份不重新公开，不承诺识别所有换网址或换站转载。

所有公共读取继续集中在 `packages/backend/src/publication/`。站内 API、页面和公共资源必须执行同一套可见性与全文条件。首版不交付的热点、事件、日报、RSS 输出和 MCP 等旧入口明确退役，不留下另一套仍可读旧内容的出口。RSS 作为输入采集方式继续保留。

下架以服务器当前状态为准，新的公共访问经过缓存重新验证后不得继续得到正文。公共正文与资源缓存统一按不超过 60 秒的可见性窗口设计，不使用延长旧内容的过期兜底；已在读者屏幕上显示或已经下载的副本无法远程收回。管理员修改及私人数据响应使用 `no-store`。

## 5 数据保存与私人空间

继续使用现有 Node.js、TypeScript、Fastify、React Router、PostgreSQL 与任务队列，保持 web 只通过 HTTP 访问 api。api 与 worker 持有数据库和采集配置，公开页面请求不调用模型。

| 数据 | 处理方式 |
| --- | --- |
| 来源、文章、规范化身份、发现记录 | 复用现有结构，保留来源归属和原文地址 |
| 人工修正与下架记录 | 复用 `editorial_overrides` 和并发版本检查 |
| 公开文章投影与搜索 | 改为从原始文章及人工修正生成；标题、摘要、标签允许没有模型结果 |
| 管理员私人阅读状态 | 新增独立记录，关联文章，保存收藏、阅读状态和更新时间 |
| 管理员读后感 | 新增独立记录，关联文章，保存文本和更新时间；更新使用版本检查避免多窗口覆盖 |
| 正文保存版本 | 按文章与内容修订保存经清洗的 HTML、文章元数据、保存时间、内容校验值与资源清单 |
| 图片资源 | 长期归档存储与可清理的图片缓存分开；保存类型、大小、校验值和存储位置 |

私人数据归单一管理员身份所有，由服务器持久化，可在同一管理员登录的不同设备使用。普通访客没有私人空间。不得将读后感或私人阅读状态加入公开文章 JSON、页面服务端渲染、搜索索引、分享信息或公共缓存。

沿用现有管理员会话和写请求 CSRF 防护。私人接口逐次检查管理员身份；不能仅凭前端隐藏按钮实现隔离。后台仍能查看已下架的内部记录和已保存内容；公开下架不等于删除你的私人资料。永久物理删除不纳入首版默认操作。

## 6 全文质量与离线保存

现有阅读器与 HTML 清洗可以作为基础，保留标题层级、列表、引用、图片、表格、代码及其语言信息。不能直接执行来源的脚本或保留任意 iframe。现有 SVG 和数学内容处理会丢失部分信息，首个真实来源验证阶段必须专门检查；需要调整的静态图表或公式保留方式，在此阶段用样本确定。遇到重要内容丢失的文章不能标成完整正文。

长期归档按确定的内容版本工作。保存正文后记录图片资源清单，资源下载完成、校验通过后才标记该版本归档完整。部分图片失败时保留已获取的内容和缺失状态，允许重试，不能用“已保存”掩盖资源缺失。正文修订与图片下载并行时，不能把不同版本的正文和图片混为一个完整版本。

原站发生内容变化时，更新当前阅读版本，并保留此前已成功保存的版本；不因一次失败抓取覆盖最后可用正文。下载和清洗继续使用已有的外部地址防护，并设置文件类型、单文件和整篇文章资源大小限制。具体限额由真实样本与存储环境确定，不在本设计中编造流量预算。

管理员可导出一篇文章的 ZIP，其中包含可直接离线打开的 HTML、Markdown、图片目录和元数据清单，图片使用包内相对地址。导出使用一个明确的版本；完整包必须在断网状态下显示该版本的正文和图片。视频、音频、第三方互动组件保留说明或原文链接，不承诺离线播放。资源不完整的包必须明确标注不完整。

公共页面使用的归档资源访问也检查文章当前公开状态和来源全文设置，不能因为文件有固定地址而绕过下架。私人归档和导出接口要求管理员身份。站点备份同时包含数据库与归档文件；现有只覆盖部分上传目录的备份流程需要扩展，并通过恢复后的内容校验。

来源的全文展示权限按来源管理，保留 `site_fulltext` 默认关闭的边界，只有确认可公开展示的来源才开启。技术抽取成功和允许公开全文是两个独立条件。目标来源的全文覆盖率需要在接入时建立清单，不能以支持 RSS 代替全文接入验收。

## 7 改造边界与实施阶段

主要改动集中于以下位置，具体文件拆分由实施计划确定：

| 范围 | 责任 |
| --- | --- |
| `packages/backend/src/content/`、`sources/`、`jobs/content.ts` | 复用采集与提取，调整无模型发布、修订处理和任务衔接 |
| `packages/backend/src/publication/` | 统一文章公开条件、原始标题与摘要、主题全部文章、筛选、搜索和下架 |
| `apps/api`、`packages/contracts` | 来源和日期筛选契约，受保护的私人阅读、笔记、归档与导出接口 |
| `apps/web` | 调整文章列表和导航，复用阅读器，增加管理员个人入口和归档状态 |
| `modules/reader/` | 承载本项目新增的私人阅读与归档能力，使用已有模块接入机制；缺少的接点再按实际需要扩展 |
| `apps/worker`、`operations/`、数据库迁移 | 精简任务、补归档与备份，更新迁移和部署说明 |
| `site/`、`industry/` | 站点身份、来源、分类、主题与实际运营说明 |

不能只隐藏热点与日报导航，却让原任务继续运行。替换和退役功能时，同一变更检查代码、任务、契约、测试、文档、配置和存储状态；删除库表使用新的迁移，不改写已发布迁移。此清理仅针对独立开发项目的全新数据库，不对原项目或未知现有数据库执行删除。

| 阶段 | 可检查的成果 | 完成条件 |
| --- | --- | --- |
| A 环境和来源样本 | 隔离工作副本、独立数据库、3 至 5 个候选来源的接入清单 | 确认来源地址、全文范围、普通文章及代码和图表样本；开发默认关闭外部模型及推送 |
| B 自动公开阅读 | 采集后自动出现，正常来源可站内阅读全文，管理员可下架 | 模型关闭仍能工作；重复采集和并发处理不会恢复已下架文章 |
| C 查找与整理 | 最新列表、具体来源、主题、日期区间和搜索 | 未入选旧文章也能按主题查找；超过原分页上限的历史记录仍可访问 |
| D 私人阅读与归档 | 收藏、阅读状态、读后感、正文图片保存与导出 | 无登录访问不到私人数据；离线包能断网阅读，备份可恢复 |
| E 发布准备 | 真实来源验收、品牌与说明、部署配置 | 完成下表检查，明确接入覆盖情况和仍受限的来源 |

阶段 B 与 C 的发布契约需要一并设计，实施可分提交，但不能交付相互矛盾的公开入口。数据库先采用全新库，暂不承担现有 AGIDawn 运营数据迁移；未来若需要迁移，先单独评估数据范围和保留要求。

## 8 验收标准

| 场景 | 必须观察到的结果 |
| --- | --- |
| 模型完全关闭 | 新来源文章仍能进入列表；正文提取成功后可直接阅读，不产生模型请求 |
| 公开访问 | 无登录可浏览、搜索并读取允许展示的全文、图片及原文链接 |
| 代表性技术文章 | 对照原文检查标题、段落、代码、表格、图表与公式；已知缺失明确标记，核心样本无重要内容丢失 |
| 元数据缺失 | 缺作者不补造，缺日期显示收录时间；后续补齐不造成重复文章 |
| 采集与修订 | 同一规范化地址只对应一篇文章；旧任务不能覆盖更新的正文或人工修正 |
| 下架 | 列表、搜索、详情和公共资源统一停止提供；缓存窗口后新请求生效；重复采集及正文修订不恢复 |
| 来源停用 | 不再采集新文章，已有公开文章按既定状态保留 |
| 筛选与历史查找 | 来源、主题、日期可组合使用；能够访问全部符合条件的已收录历史记录 |
| 私人数据隔离 | 未登录请求私人接口被拒绝；公开 HTML、JSON 和搜索均不含笔记、收藏和个人状态 |
| 多窗口编辑 | 旧版本笔记保存不会静默覆盖新版本；冲突时保留用户输入并提示重新载入 |
| 离线导出 | ZIP 解压后断网打开 HTML 和 Markdown，正文与已归档图片可用；缺失资源有明确清单 |
| 备份恢复 | 在另一空数据库及资源目录恢复后，文章、私人笔记与归档文件保持一致 |
| 旧入口退役 | 未交付的旧公开 API、RSS 输出、MCP、热点和报告入口不泄露另一套内容或继续触发任务 |

验证分为本地假源的可重复测试和真实来源的阅读对照。本地测试不调用付费模型、不发送通知；真实来源检查只在接入阶段按明确清单执行。改造后运行项目要求的类型检查、相关后端测试、前端构建和测试，以及运行中的站点 smoke 检查；已有 smoke 与架构测试需按新产品的正式契约同步更新，不能直接绕过检查。
