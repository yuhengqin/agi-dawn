# 正文组件转换设计

使用者已确认采用轻量处理管道、转换策略和来源适配，并授权实现。现有提取会去掉原站样式，Browser Use 的作者名单、响应式图表和图例因此变得难读。

## 范围与选择

沿用 Readability、安全清洗、现有来源声明式规则及正文质量状态；不增加依赖、数据库迁移或新的正文存储格式。将页面预处理与组件转换从 `extract.ts` 分离，用函数注册表选择转换器，并增加显式的 `detail.bodyAdapter: "browser-use"` 来源配置。

单纯继续添加条件容易把来源识别和通用清洗耦合；引入完整内容 AST 或浏览器截图服务会扩大部署与存储范围。本次选择已有 HTML 管道和小型适配器。

## 行为

- 来源适配在 Readability 和去样式前运行；未选择适配器的来源维持现有行为。
- 现有 `preserve` 的代码块与描述列表转表格能力采用注册的通用转换器；保留隐藏状态及安全文本写入。
- Browser Use 作者名单转成紧凑段落，作者相邻的日期与类别之间保留分隔。
- Odysseys2 的完成数量列表、推理力度结果、双评判结果在能完整验证结构时转换为表格；移除同一组件的重复绘图和已由列名表达的图例。
- 两个绘图版本的数据有分歧、行不完整或遇到未知图表时不猜测数据，继续走现有图形/文字降级，并保留不完整提示。
- 链条图标、公式、代码、媒体与已有来源规则保持既有处理。
- 初次交付仅生成可审查代码；不修改运行数据库配置，不重采、不翻译存量文章，不切换服务。后续已获使用者明确授权本地提交并合回 main，不推送远端。
