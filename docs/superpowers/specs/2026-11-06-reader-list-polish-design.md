# 文章列表交互与桌面浏览优化

用户在 Chrome 实机评审五项问题后明确要求全部优化。本次沿用该范围，由实现者完成可逆工程选择，验证后同步本机运行版本；不提交或推送 Git，不公开部署，不迁移或整理真实数据。

## 目标与边界

- 连续搜索、来源、类别、主题、日期和分页操作以最新在途条件组合，迟到响应不恢复旧条件。
- 保留 300ms 搜索防抖、中文组词保护、离开时取消尚未提交的搜索，以及日期草稿确认/取消语义。请求进行期间新输入的文字不能被旧请求完成覆盖。
- 桌面收紧列表上下留白，保留 20px 标题、15px 摘要和最多两行摘要，目标是在 1280×800 的代表性列表中完整展示四篇。
- 桌面搜索、来源、日期组成紧凑吸顶工具栏。主题导航和结果计数随正文滚动；工具栏不遮住键盘焦点，日期浮层在窗口内可操作。
- 空结果正文提供“移除来源限制”“清除关键词”，各自仅移除一个条件，保留其余筛选及每页篇数，回到第一页。日期空结果保留原有恢复操作。
- 核对服务工作副本、端口、数据库及归档目录归属后，同步已验证代码与 web 构建，并仅重启需要加载新版本的本机服务。
- 范围为桌面浏览器；不扩展来源、分类含义、全文许可、私人资料或外部动作授权。

## 实现选择

筛选采用 React Router 已有的在途目标地址作为下一次操作的输入。它能覆盖工具栏、侧栏、主题链接和分页，又不引入第二套全局筛选状态。只在搜索框保留必要的本地输入草稿及防抖。禁用全部筛选等待返回会降低连续操作效率；新增全局状态容器则增加 URL 与状态同步成本，均不采用。

吸顶采用原生 `position: sticky`，不加入滚动收缩动画。仅测量工具栏实际高度以给浏览器焦点滚动留出位置，保持长来源、日期范围和桌面缩放下的可用性。列表密度通过桌面样式调整，不新增显示模式。

## 验收

用假 API 的受控慢响应验证搜索后切来源、来源后切类别/主题/日期、日期后继续搜索、清条件及每页篇数；验证旧请求释放后最终地址与界面不回退。沿用现有输入法、日期草稿、无 JS、历史/焦点回归。通过类型检查、web 构建和受影响 web 测试后，使用 Chrome 核对桌面布局、深色、缩放与真实运行页面。
