# 网页主题管理

用户已授权在本机 Linux 实现主题列表、关联文章数、新增、改名及编辑说明，并同步私人筛选、单篇勾选和批量整理，保持已有文章归属；不公开上线。

主题管理使用管理员入口 `/admin/reader/topics`。列表展示名称、说明、按私人书库范围统计的关联篇数，以及进入该主题书库的链接；篇数包含下架和停用来源的已发布历史。新增填写名称和说明，编辑可同时改这两项。名称去首尾空白后1–60字符且不能含换行/NUL；说明去首尾空白后1–2000字符且不能含NUL。名称唯一。成功和错误有明确反馈，失败保留输入，冲突提供显式载入已保存版本；会话失效卸载私人界面。

现有14项从 `industry/topics.json` 幂等初始化到新表 `article_topics`，原slug、匹配标签和顺序逐项保留。文件保留为首次初始化模板，运行时不再从文件读取主题项；重复初始化不覆盖后台编辑。分组继续沿用配置，本批新增技术主题使用field分组，不提供分组管理。

主题目录以数据库为唯一运行时来源。改名与编辑说明不改slug或匹配标签，不重写人工覆盖、发布投影、来源、原文、笔记、状态或快照。新增使用独立稳定slug和内部匹配标签，避免与旧名称碰撞；内部标记不作为面向读者的普通标签显示。保存后各入口的下一次读取立即生效，无需重启API，不增加目录缓存或轮询。

选择保留匹配标签而非迁移文章关系：后者会改变现有源标签继承和逐篇编辑规则，且需要改写用户数据。直接写JSON不能提供可靠的并发版本检查及数据库审计，也不能让多个后端进程即时看到新值，因此采用数据库目录。

管理写入严格校验会话、CSRF和版本；重名及旧版本拒绝，审计和写入同事务。管理端篇数与私人书库主题筛选保持一致；普通主题页继续只统计公开可见文章。只提供新增和名称/说明更新，既有文章的主题勾选、增量整理及隐藏标签保留规则继续有效。

前端沿用现有样式、原生表单及48px控件，输入有可见标签，表单分组，编辑失败不清空草稿，保存期间禁止重复提交。保存成功后若刷新目录失败，原地保留列表和其他表单草稿，显示刷新错误和只读重试入口，不重复提交已保存的修改；会话失效仍卸载私人界面。测试覆盖初始化不覆盖编辑、改名归属不变、旧链接与筛选继续有效、新主题在所有入口可用、计数范围、并发和审计回滚、无登录/无CSRF拒绝。真实库先停服务备份，再迁移和初始化；已有业务表前后摘要核对，网页真实验收以读取和取消为主，写入行为在隔离测试库验证。
