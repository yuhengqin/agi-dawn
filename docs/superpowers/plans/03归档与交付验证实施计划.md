# 归档、离线保存与交付验证实施计划

> **执行记录：** T10—T13及T14本机范围已完成，见[验收记录](../../reader/acceptance.md)、[恢复记录](../../reader/backup-restore.md)与主计划清单。模块迁移实际放在 `modules/reader/migrations/`，离线浏览器检查包含在模块export测试；下文保留原计划步骤，不虚称已执行全部预想进程崩溃注入。正式上线未执行。

**Goal:** 保存确定版本的正文和图片，提供可断网阅读的单篇 ZIP，并以实际恢复和真实来源对照完成交付验收。

**Architecture:** `modules/reader` 保存不可变快照与内容寻址资源。核心在正文事务中传递确定材料，publication 只引用对应版本的资源；备份将数据库和归档文件作为一组处理。

**Tech Stack:** 现有 PostgreSQL、pg-boss、Node 文件流、HTTP 地址防护、HTML 清洗和 Markdown 转换；ZIP 库在 T12 核实锁定版本后加入直接依赖。

**Spec:** [已确认设计](../specs/AGIDawn改造设计方案.md)；[全局约束、依赖和 Q1—Q7 命令](../plans/AGIDawn实施计划.md)。源码路径均相对于未来独立工作副本。

## Global Constraints

归档目录不属于可定期清理的图片缓存。正文、元数据和资源必须来自指定快照；正文缺失重要内容或必要图片未保存时不能标 complete。公开文件逐次执行当前文章权限，私人版本和导出要求管理员身份。不能把私有笔记默认打进可分享的文章 ZIP。

## Review Focus

正文写入与队列入列原子性；旧修订晚到与仅 HTML 表示变化；下载中断和重复执行；权限撤销后的图片、304 与旧代理地址；ZIP 路径与外部请求；数据库 dump 和文件集合在并发新增期间的一致性。

## T10 不可变正文快照及事务接点

**Files:** 创建 `modules/reader/archive/snapshots.ts`、`modules/reader/tests/snapshots.test.ts`；修改模块 `contracts.ts`、`server.ts`，核心 `packages/backend/src/modules.ts`、`content/materials.ts` 及 T03 中实际提交正文的事务位置。新增单语句迁移 `database/migrations/0093_reader_snapshots.sql`、`0096_reader_snapshot_ready_idx.sql`。

**Interfaces:** `MaterialCapture = {articleId, bodyRevision, bodyHtml, title, author, originalUrl, publishedAt, discoveredAt, sourceId, sourceName, quality, issues}`，字段值取自这次事务实际写入的材料；`EngineHooks.articleMaterialStored(capture: MaterialCapture, tx: Db): Promise<void>`。`ArchiveSnapshot` 含 ID、材料版本、representationHash、内容及元数据、createdAt/completedAt、formatVersion 与 `pending | partial | complete` 状态。

`representationHash` 对规范化 HTML、正文质量与快照元数据确定性编码后取 SHA-256；唯一键为 `(article_id, body_revision, representation_hash)`。同正文修订但 HTML 图表、标题或来源元数据改变时可生成新表示；同一输入重试只得到同一快照。快照正文与元数据创建后不覆写，资源处理状态可推进。

## T11 图片归档、资源授权与中断恢复

**Files:** 创建 `modules/reader/archive/{assets,verify}.ts`、`modules/reader/tests/{assets,asset-access}.test.ts`；修改模块 `contracts.ts`、`server.ts`、`module.ts`，核心 `packages/backend/src/modules.ts`、`publication/detail.ts`、`media/{images,imgproxy}.ts`、`apps/api/src/routes/media.ts` 以及引用旧图片代理的保留消费者。新增单语句迁移 `database/migrations/0094_reader_assets.sql`、`0095_reader_snapshot_assets.sql`。配置与部署文档补充归档目录及限额。

**Interfaces:** `ArchiveLimits = {maxAssetBytes, maxSnapshotBytes, maxAssetsPerSnapshot, downloadConcurrency, timeoutMs}`；根据 T01 来源样本及目标磁盘在本任务确定具体值并记录，所有值必须是有限正数。`reader_assets` 保存 SHA-256、MIME、字节数、相对路径；`reader_snapshot_assets` 保存 snapshotId、原资源地址/引用、assetHash、状态及失败原因。

最终文件位于 `data/reader-archives/assets/<hash>.<ext>`，先写受控临时文件、校验并原子改名，再提交数据库 ready 引用；文件提交后不原地修改。重试只补缺失资源，complete 后资源映射冻结，不能用同 URL 后来下载的另一张图片静默替换。

公开路由 `GET /api/reader/articles/:articleId/assets/:snapshotId/:assetKey` 逐次检查 `canReadArticleBody`、文章和快照归属、当前 bodyRevision 与 representationHash，随后才允许返回文件或 304；响应 no-store。管理员对应路由 `/api/admin/reader/snapshots/:snapshotId/assets/:assetKey` 可读历史版本，要求有效会话。

## T13 配套备份与实际恢复

**Files:** 修改 `packages/backend/src/operations/backup.ts`、模块配置及部署说明；创建 `modules/reader/archive/backup.ts`、`scripts/verify-reader-archive.ts`、`docs/reader/backup-restore.md`，扩展 `tests/backup.test.ts`、创建 `modules/reader/tests/backup-restore.test.ts`。需要模块备份目录接点时在 `packages/backend/src/modules.ts` 声明纯目录/清单接口，不让核心导入 reader 模块。

**Interfaces:** 备份组清单记录同组数据库 dump、文件归档、格式版本、文件大小和哈希；只有全部产物验证成功才有 complete 标记。`node scripts/verify-reader-archive.ts --data-dir <恢复目录>` 连接恢复库，检查所有已提交 ready 资源的文件、大小和 SHA-256，缺失/损坏返回非零退出码。

一致性策略：首版保留所有已提交归档资源，不做自动物理 GC。先完成数据库一致性 dump，再打包归档资源，包含 dump 所引用文件的超集是允许的；新增文件只能在完整落盘后被数据库引用。冻结打包文件清单，排除临时文件，不把目录打包过程中新文件加入同一清单；禁止备份期间删除已提交资源。数据库备份记录 pending 任务时，恢复后按快照清单重新排队。
