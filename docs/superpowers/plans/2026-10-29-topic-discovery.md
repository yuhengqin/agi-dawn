# 主题浏览恢复实施计划

**目标：** 按站主确认的建议，保留现有技术主题，恢复内容导览与双向导航，修复切换主题和公开列表分页。

**设计：** 复用 main 的响应式卡片思路和现有样式令牌。桌面使用三至四列卡片，手机使用整行链接；展示总篇数、近30天篇数、最新文章和更新时间，空主题明确提示。主题内页展示定义、统计及返回目录，文章页展示所属主题。继续使用数据库主题目录与现有公开读取层，不增加配置、依赖、迁移或模型调用。

**取舍：** 不恢复 main 的公司/内容形态主题及精选机制；不另建主题数据接口，直接消费已有 TopicSummary。主题切换使用 GET 后的服务端重定向，保留其他筛选并移除旧游标；“全部主题”进入全部文章。分页保留数据库原始微秒时间，以文章ID处理相同时间排序。

**技术栈：** Node.js 24、TypeScript、React Router、Tailwind CSS、PostgreSQL、node:test、Playwright。

## 约束与验收重点

- 在既有 codex/article-reader 工作树修改；不改主题词表、私人状态和来源权限。
- 主题切换、刷新、清除和更早文章的 URL、控件与结果一致；其他筛选保留。
- 同一毫秒内不同微秒及相同时刻的文章翻页无遗漏、无重复，游标仍绑定筛选。
- 空主题、没有最新文章和较长标题有清楚展示；手机与桌面可返回目录。
- 文章所属主题可进入对应列表；主题管理改名后继续使用稳定 slug。
- 回归测试加入现有测试文件；视觉样式通过浏览器验收，不断言CSS或像素。
